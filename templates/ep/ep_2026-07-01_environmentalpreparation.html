1. 実験の目的

本実験では、サーバー仮想化技術（KVM）とコンテナ技術（Docker）の性能を定量的に比較・分析し、それぞれの特性と適用条件を明らかにするとともに、用途に応じた効率的な運用方法を検討します。

具体的には、各仮想化環境（VM単体・Docker単体・VM上Docker）のCPU、メモリ、ストレージ、ネットワーク性能の差異、CPUアフィニティやCPU割り当て方法の影響を調べ、用途ごとの選定指針を提示します。

2. 実験環境

2-1. ホストOS

  • OS：Ubuntu Server 26.04 LTS（Resolute Raccoon）
  • カーネル：GNU/Linux 7.00-27-generic
  • アーキテクチャ：x86_64（amd64）

Ubuntu 26.04.1公開後には同一手順で再実験し、結果の再現性を確認します。

2-2. 比較対象の4環境

以下の4環境を構築し、同一の測定条件で性能を比較します。

環境構成概要
AホストOS（Ubuntu）ホストOS上で直接ベンチマークを実行する比較基準
BVM単体KVM/QEMUでUbuntu VMを構築し、VM内で実行
CDocker単体ホストOS上のDockerコンテナ内で実行
DVM上DockerKVMのVM内にDockerを構築し、コンテナ内で実行

2-3. 測定ツールと測定項目

測定項目ツール主な指標実行例
CPU性能SysBench演算速度・スループットsysbench cpu --threads=4 --time=30 run
メモリ性能SysBench帯域幅・レイテンシsysbench memory --memory-total-size=10G run
ストレージI/OfioIOPS・スループット・レイテンシfio --rw=randread --bs=4k --direct=1 ...

4. KVM環境の構築

4-1. 必要なパッケージのインストール

システムを更新した後、KVM関連のツールをインストールします。

sudo apt update && sudo apt upgrade -y
sudo apt install -y \
  qemu-kvm \
  libvirt-daemon-system \
  libvirt-clients \
  bridge-utils \
  virt-manager \
  virtinst
パッケージ名役割
qemu-kvmQEMUエミュレーター（KVMのバックエンド）
libvirt-daemon-systemlibvirtデーモン（VM管理API）
libvirt-clientsvirshコマンドラインクライアント
bridge-utilsブリッジネットワーク設定ツール
virt-managerGUIベースの仮想マシン管理ツール
virtinstvirt-installコマンド（CLIでVM作成）

4-2. libvirtサービスの起動

サービスを起動し、自動起動を有効にします。

sudo systemctl enable --now libvirtd
sudo systemctl status libvirtd

5. KVMの動作確認

5-1. 仮想マシン一覧

virsh list --all

初期状態ではVMが登録されていないため、空の一覧が表示されます。

5-2. 仮想ネットワーク一覧

virsh net-list --all

defaultネットワークがactiveになっていることを確認します。

5-3. defaultネットワークがinactiveの場合

以下を実行してネットワークを起動し、自動起動を有効にします。

sudo virsh net-start default
sudo virsh net-autostart default
virsh net-list --all

defaultがactiveと表示されれば設定完了です。
