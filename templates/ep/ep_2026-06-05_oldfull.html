1. 実験の目的

本実験では、サーバー仮想化技術（KVM）とコンテナ技術（Docker）の性能差を定量的に比較し、各技術の特徴と適した運用条件を明確にすることを目的とする。

特に、VM 単体、Docker 単体、VM 上 Docker の3つの環境を同一の測定条件で比較し、CPU・メモリ・ストレージ・ネットワーク性能の差異を評価する。さらに、CPU アフィニティなどの設定変更が性能にどのような影響を与えるかを確認し、用途ごとの最適な構成を整理する。

2. 実験環境

2-1. ホスト環境

項目内容
OSUbuntu Server 26.04 LTS（Resolute Raccoon）
カーネルLinux 7.0
アーキテクチャx86_64（amd64）
補足ポイントリリースである Ubuntu 26.04.1 の公開後に、同一手順を再実施して再現性を確認する。

2-2. 比較対象

環境構成概要
環境 AVM 単体ホスト OS 上に KVM/QEMU で Ubuntu VM を構築し、VM 内で直接ベンチマークを実行する。
環境 BDocker 単体ホスト OS 上で Docker Engine を起動し、Ubuntu コンテナ内でベンチマークを実行する。
環境 CVM 上 DockerKVM の VM 内に Docker を構築し、コンテナ内でベンチマークを実行する（二重仮想化）。

2-3. 測定ツールと測定項目

3. 導入手順

3-1. 仮想化環境の準備

インストール前に CPU が仮想化支援機能をサポートしているか確認する。

grep -E 'vmx|svm' /proc/cpuinfo | head -5
lscpu | grep Virtualization

仮想化機能が有効でない場合は BIOS/UEFI の設定から Virtualization Technology を有効にする。

3-1-1. パッケージのインストール

sudo apt update && sudo apt upgrade -y
sudo apt install -y qemu-kvm libvirt-daemon-system libvirt-clients \
    bridge-utils virt-manager virtinst
パッケージ役割
qemu-kvmQEMU エミュレータ（KVM のバックエンド）
libvirt-daemon-systemlibvirt デーモン（VM 管理 API）
libvirt-clientsvirsh コマンドラインクライアント
bridge-utilsブリッジネットワーク設定ユーティリティ
virt-managerGUI ベースの VM 管理ツール
virtinstvirt-install コマンド（CLI で VM 作成）

3-1-2. ユーザーのグループ追加

sudo usermod -aG libvirt,kvm $(whoami)
newgrp libvirt

3-1-3. libvirt の起動

sudo systemctl enable --now libvirtd
sudo systemctl status libvirtd
virsh list --all
virsh net-list --all

default ネットワークが inactive の場合は、次のコマンドで起動し自動起動を設定する。

sudo virsh net-start default
sudo virsh net-autostart default

3-1-4. VM の作成

virt-install \
  --name ubuntu-vm \
  --ram 2048 \
  --vcpus 2 \
  --disk path=/var/lib/libvirt/images/ubuntu-vm.qcow2,size=20 \
  --os-variant ubuntu24.04 \
  --cdrom /path/to/ubuntu-24.04.iso \
  --network network=default \
  --graphics none \
  --console pty,target_type=serial

3-2. Docker の構築

sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo \
  "deb [arch=$(dpkg --print-architecture) \
  signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin

sudo usermod -aG docker $(whoami)
newgrp docker
sudo systemctl enable --now docker

docker run hello-world

3-3. ベンチマークツールの導入

sudo apt update
sudo apt install -y sysbench fio iperf3

3-3-1. SysBench

sysbench cpu --cpu-max-prime=20000 --threads=4 --time=30 run
sysbench memory --memory-total-size=10G --threads=4 run

3-3-2. fio

fio --name=rand-read --ioengine=libaio --direct=1 \
    --rw=randread --bs=4k --iodepth=16 \
    --size=1G --runtime=30 --time_based \
    --filename=/tmp/fio-test.dat --output-format=json

3-3-3. iperf3

iperf3 -s
# TCP
iperf3 -c <サーバーIPアドレス> -t 10 -P 4 --json
# UDP
iperf3 -c <サーバーIPアドレス> -u -b 1G -t 10 --json

3-4. VM 上 Docker の構築

  1. KVM で Ubuntu VM を起動し、SSH でログインする。
  2. VM 内で「Docker の構築」の手順をそのまま実施する。
  3. ベンチマークツール（sysbench・fio・iperf3）を VM 内でも同様にインストールする。
  4. Docker コンテナ内でベンチマークを実行し、ホスト直接実行との比較データを取得する。

ネスト仮想化が必要な場合は、Intel なら sudo modprobe kvm_intel nested=1 を使用する。

4. 実験の大まかな予定

Ph.時期フェーズ名主な作業内容

26月中旬～下旬初回ベンチマーク環境 A・B・C で CPU / メモリ / ストレージ / ネットワークの測定
37月17日中間報告進捗確認と調整
48月6日（予定）Ubuntu 26.04.1 更新OS を 26.04.1 に更新し、同条件で再測定

68月下旬追加検証CPU アフィニティの ON/OFF 影響を確認
79月以降分析・グラフ化測定結果を整理し、要因分析と考察を行う

4-1. 測定手順の概要

  1. 3 環境に対して共通のベンチマークツールをインストールする。
  2. アイドル状態を確認してから測定を開始する。
  3. 各測定を 3 回実施し、中央値を採用する。
  4. 結果を JSON 形式で保存し、表計算ソフトやグラフで比較する。
  5. 測定後は不要なテストファイルを削除する。

5. 比較条件・注意事項

  • 同一のハードウェア条件と負荷条件で測定を行う。
  • 各環境では CPU 使用率・メモリ使用量・I/O 状態のベースラインを揃える。
  • 再測定時は OS バージョン差異と設定変更を記録する。
  • 異常値が現れた場合は再現性確認を行い、データ採用の妥当性を検討する。
